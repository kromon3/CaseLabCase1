# Weather Digest — консольный «Погодный дайджест»

Утилита на Node.js принимает название города (или несколько городов), получает прогноз погоды
из открытого REST API [Open-Meteo](https://open-meteo.com/), выводит результат таблицей
в терминал и сохраняет отчёт в JSON-файл. Ключ доступа к API не нужен.

Данные собираются цепочкой из двух связанных запросов: сначала геокодинг
(название города → координаты), затем прогноз по этим координатам. Города обрабатываются
параллельно, ошибка по одному городу не прерывает остальные. Отчёт за текущую дату
кэшируется в файле — повторный запуск не ходит в сеть.

## Требования к окружению

- Node.js **20 или новее** — используются встроенный `fetch`, `AbortController`,
  `node:util.parseArgs`, `node:test` и флаг `--env-file`;
- npm 10+ (нужен только для dev-инструментов: ESLint и Prettier; у самой утилиты
  runtime-зависимостей нет);
- сторонние HTTP-клиенты (axios и аналоги) не используются.

```bash
node -v
```

## Установка

```bash
git clone https://github.com/kromon3/CaseLabCase1.git

npm install
cp .env.example .env
```

## Переменные окружения

Все настраиваемые параметры вынесены в окружение. Файл `.env` в репозиторий не попадает
(он в `.gitignore`), шаблон лежит в [`.env.example`](.env.example). Единственное место,
где читается `process.env`, — [`src/config.js`](src/config.js).

| Переменная              | По умолчанию                                     | Назначение                                                          |
| ----------------------- | ------------------------------------------------ | ------------------------------------------------------------------- |
| `GEOCODING_API_URL`     | `https://geocoding-api.open-meteo.com/v1/search` | базовый URL геокодинга                                              |
| `FORECAST_API_URL`      | `https://api.open-meteo.com/v1/forecast`         | базовый URL прогноза                                                |
| `REQUEST_TIMEOUT_MS`    | `5000`                                           | таймаут одного HTTP-запроса, мс (`AbortController`)                 |
| `REPORTS_DIR`           | `reports`                                        | каталог для сохранения отчётов                                      |
| `DEFAULT_FORECAST_DAYS` | `3`                                              | число дней прогноза, если `--days` не передан                       |
| `TEMPERATURE_UNIT`      | `celsius`                                        | единицы температуры: `celsius` или `fahrenheit`                     |
| `PRECIPITATION_UNIT`    | `mm`                                             | единицы осадков: `mm` или `inch`                                    |
| `GEOCODING_LANGUAGE`    | `ru`                                             | язык названий в ответе геокодинга                                   |
| `FORECAST_TIMEZONE`     | `auto`                                           | часовой пояс дат прогноза                                           |
| `CITY`                  | —                                                | город(а) по умолчанию, если `--city` не передан (удобно для Docker) |

Загрузить `.env` можно штатным флагом Node.js:

```bash
node --env-file=.env src/index.js --city "Казань"
```

## Запуск

```bash
node src/index.js --city "Нижний Новгород" --days 3
```

```bash

```

```bash
# принудительно обратиться к сети, игнорируя сохранённый за сегодня отчёт

```

```bash
# справка

```

### Параметры командной строки

| Параметр       | Обязательный | По умолчанию            | Описание                                                    |
| -------------- | ------------ | ----------------------- | ----------------------------------------------------------- |
| `--city`       | да\*         | —                       | город или список городов через запятую; дубликаты убираются |
| `--days`       | нет          | `DEFAULT_FORECAST_DAYS` | число дней прогноза, целое от 1 до 7                        |
| `--no-cache`   | нет          | выключен                | не использовать сохранённый отчёт за сегодня                |
| `--help`, `-h` | нет          | —                       | справка по параметрам                                       |

\* если `--city` не передан, берётся переменная окружения `CITY`; если нет и её — ошибка.

### Кэширование

Отчёт сохраняется в `reports/{город}-{ГГГГ-ММ-ДД}.json`, где `{город}` — введённое название
в нижнем регистре с дефисами вместо пробелов (`нижний-новгород-2026-09-20.json`). Если файл
за текущую дату уже существует и в нём не меньше дней, чем запрошено, данные берутся из него
без обращения к сети (в выводе это отмечается строкой «Данные взяты из сохранённого отчёта»).
Если в кэше дней меньше, чем запрошено, прогноз запрашивается заново и файл перезаписывается.
Флаг `--no-cache` всегда выполняет запрос заново. Повреждённый файл кэша не считается ошибкой.

## Обрабатываемые ошибки и коды завершения

Код завершения процесса: `0` — успех, `1` — ошибка (в том числе если хотя бы один город
завершился ошибкой). Стек-трейсы пользователю не показываются.

| Ситуация                     | Сообщение пользователю                                                |
| ---------------------------- | --------------------------------------------------------------------- |
| не передан `--city`          | Не указан обязательный параметр --city.                               |
| `--city` без значения        | Некорректные аргументы командной строки.                              |
| некорректный `--days`        | Параметр --days должен быть целым числом от 1 до 7.                   |
| неизвестный параметр         | Неизвестный параметр: --foo.                                          |
| город не найден              | Город «...» не найден.                                                |
| ответ API со статусом 4xx    | Сервис отклонил запрос (код 400): причина из ответа API               |
| ответ API со статусом 5xx    | Сервис погоды временно недоступен (код 503). Повторите попытку позже. |
| отсутствие сети              | Нет связи с сервисом погоды. Проверьте подключение к сети.            |
| превышение таймаута          | Превышено время ожидания ответа (5000 мс).                            |
| некорректный JSON в ответе   | Сервис вернул некорректный ответ (ожидался JSON).                     |
| неожиданная структура ответа | Сервис вернул ответ неожиданной структуры.                            |
| всё остальное                | Непредвиденная ошибка.                                                |

При ошибке аргументов дополнительно печатаются строка использования и подсказка про `--help`.
Подробная таблица с типами ошибок и местами их обработки — в [`docs/errors.md`](docs/errors.md).

Как воспроизвести сценарии вручную:

```bash
REQUEST_TIMEOUT_MS=1 node src/index.js --city Казань --no-cache          # таймаут
```

```bash
GEOCODING_API_URL=http://localhost:9/search node src/index.js --city Казань   # нет сети
```

```bash
FORECAST_API_URL=https://httpbin.org/status/503 node src/index.js --city Казань --no-cache   # 5xx
```

```bash
FORECAST_API_URL=https://httpbin.org/html node src/index.js --city Казань --no-cache   # не JSON
```

В PowerShell переменная задаётся отдельно: `$env:REQUEST_TIMEOUT_MS = 1; node src/index.js --city Казань --no-cache`.

## Структура проекта

```text
src/
  index.js               точка входа: разбор аргументов, запуск сценария, код выхода
  config.js              единственное место чтения process.env
  cli/
    args.js              разбор argv (node:util.parseArgs), текст справки
    validate.js          проверка аргументов, без сети и файлов
  api/
    httpClient.js        обёртка над fetch: URL, AbortController, статусы, JSON
    geocoding.js         запрос 1: координаты по названию города
    forecast.js          запрос 2: прогноз по координатам
  services/
    weatherService.js    бизнес-логика: город -> отчёт, кэш, Promise.allSettled
  storage/
    paths.js             имена файлов отчётов (модуль path)
    reportStore.js       чтение и запись отчётов (fs/promises)
  format/
    table.js             сборка строк вывода: шапка города и таблица по дням
    messages.js          все тексты сообщений в одном месте
  errors/
    AppError.js          типы ошибок приложения
    handler.js           единая обработка ошибок и код выхода
tests/                   тесты node:test (сеть подменяется, каталог отчётов — временный)
docs/
  errors.md              таблица обрабатываемых ошибок
  postman/               коллекция и окружение Postman с примерами ответов
public/
  index.html             страница просмотра сохранённого отчёта (DOM API)
reports/                 сохранённые отчёты, в репозиторий не попадают
Dockerfile, .dockerignore
eslint.config.js, .prettierrc.json, .editorconfig
```

## Проверка кода и тесты

```bash
npm run check
```

Тесты не ходят в сеть: `fetch` подменяется через `node:test` mock, каталог отчётов — временный.
Покрыты разбор аргументов, разбор ответов API, все ошибочные сценарии HTTP-клиента
(4xx, 5xx, нет сети, таймаут, некорректный JSON), кэш и параллельная обработка городов.

## Docker

```bash
docker build -t weather-digest .
```

```bash
docker run --rm -v "$PWD/reports:/app/reports" weather-digest --city "Казань" --days 3
```

Параметры можно передавать переменными окружения — как настройки, так и сами города:

```bash
docker run --rm -e CITY="Казань,Самара" -e DEFAULT_FORECAST_DAYS=5 -e REQUEST_TIMEOUT_MS=8000 -v "$PWD/reports:/app/reports" weather-digest
```

```bash
docker run --rm --env-file .env -v "$PWD/reports:/app/reports" weather-digest --city "Уфа"
```

В PowerShell вместо `$PWD` используйте `${PWD}`: `-v "${PWD}/reports:/app/reports"`.

## Просмотр отчёта в браузере

Откройте [`public/index.html`](public/index.html) двойным щелчком (сервер не нужен) и выберите
файл из `reports/` — страница разберёт JSON и построит таблицу средствами
DOM API (`createElement` / `append` / `textContent`, без `innerHTML` и библиотек).

## Postman

Коллекция с обоими запросами, переменными (`{{geocodingBaseUrl}}`, `{{forecastBaseUrl}}`,
`{{city}}`, `{{lat}}`, `{{lon}}`, `{{days}}`) и сохранёнными примерами ответов (200 — успех,
200 без `results` — город не найден, 400 — некорректные параметры) лежит в
[`docs/postman/`](docs/postman/README.md).

## Ветки и порядок работы

В `main` — только начальная инициализация репозитория. Каждая задача ведётся в отдельной ветке
и вливается в `main` через Pull Request после code review.

| Ветка                 | Зона ответственности                                               |
| --------------------- | ------------------------------------------------------------------ |
| `feat/cli`            | разбор и валидация аргументов, справка, форматирование вывода      |
| `feat/api-client`     | HTTP-клиент, запросы геокодинга и прогноза, параллельная обработка |
| `feat/report-cache`   | сохранение отчётов в JSON и кэш за текущую дату                    |
| `feat/error-handling` | единая обработка ошибок, коды завершения, документация ошибок      |
| `feat/bonus`          | Dockerfile, HTML-страница просмотра отчёта                         |
| `docs/readme-postman` | README, коллекция Postman                                          |

Сообщения коммитов — в стиле Conventional Commits: `feat`, `fix`, `refactor`, `docs`, `test`, `chore`.
