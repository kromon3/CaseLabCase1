# Обрабатываемые ошибки и коды завершения

Коды завершения процесса: `0` — успех, `1` — ошибка (в том числе если хотя бы один из городов
завершился ошибкой).

| Ситуация                     | Как определяется                                     | Тип ошибки        | Сообщение пользователю                                                   |
| ---------------------------- | ---------------------------------------------------- | ----------------- | ------------------------------------------------------------------------ |
| Не передан `--city`          | `validateArgs`: пустой список городов                | `ValidationError` | Не указан обязательный параметр --city.                                  |
| `--city` без значения        | любая другая ошибка `node:util.parseArgs`            | `ValidationError` | Некорректные аргументы командной строки.                                 |
| Некорректный `--days`        | не целое число или вне диапазона 1..7                | `ValidationError` | Параметр --days должен быть целым числом от 1 до 7.                      |
| Неизвестный параметр         | `parseArgs`: `ERR_PARSE_ARGS_UNKNOWN_OPTION`         | `ValidationError` | Неизвестный параметр: --foo.                                             |
| Город не найден              | геокодинг вернул 200 без поля `results` (или пустой) | `NotFoundError`   | Город «...» не найден.                                                   |
| Ответ 4xx                    | `response.ok === false`, статус 400–499              | `ApiError`        | Сервис отклонил запрос (код 400): причина из тела ответа, если она есть. |
| Ответ 5xx                    | `response.ok === false`, статус ≥ 500                | `ApiError`        | Сервис погоды временно недоступен (код 503). Повторите попытку позже.    |
| Нет сети / DNS / отказ       | `fetch` бросает `TypeError('fetch failed')`          | `NetworkError`    | Нет связи с сервисом погоды. Проверьте подключение к сети.               |
| Превышен таймаут             | `AbortController` → `error.name === 'AbortError'`    | `TimeoutError`    | Превышено время ожидания ответа (5000 мс).                               |
| Некорректный JSON            | `response.json()` бросает `SyntaxError`              | `ParseError`      | Сервис вернул некорректный ответ (ожидался JSON).                        |
| Неожиданная структура ответа | нет `daily` / массива дат, нет координат у города    | `ParseError`      | Сервис вернул ответ неожиданной структуры.                               |
| Всё остальное                | не `AppError` (например, ошибка файловой системы)    | —                 | Непредвиденная ошибка.                                                   |

## Где что обрабатывается

- `src/cli/args.js`, `src/cli/validate.js` — ошибки аргументов. Кроме сообщения пользователь видит
  строку использования и подсказку про `--help`.
- `src/api/httpClient.js` — всё, что связано с HTTP: таймаут, сеть, статусы, разбор JSON.
  Типизированные ошибки создаются в одном месте, выше по стеку текст исключений не разбирается.
- `src/api/geocoding.js`, `src/api/forecast.js` — проверка структуры ответа конкретного API.
- `src/services/weatherService.js` — `Promise.allSettled`: ошибка по одному городу становится
  элементом результата, а не исключением.
- `src/errors/handler.js` — единая точка: `toUserMessage` выбирает текст по типу ошибки,
  `fail` пишет его в stderr и выставляет `process.exitCode = 1`, `registerGlobalHandlers` —
  страховка от непойманных исключений и unhandled rejection.

## Правила

- Стек-трейс пользователю не показывается; исходное исключение сохраняется в `error.cause`
  (пригодится при отладке).
- Сообщения об ошибках идут в **stderr**, отчёты — в **stdout**: вывод можно перенаправлять
  раздельно (`node src/index.js --city Казань 2>errors.log`).
- Используется `process.exitCode`, а не `process.exit()`, чтобы потоки вывода успели дописаться.
- Повреждённый файл кэша не считается ошибкой — данные просто запрашиваются заново.
